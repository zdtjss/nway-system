# nway-system 外部系统对接文档

> 版本：2026-11（新增「接入方式决策」：区分平台承载的微前端子应用与独立外部系统；开放平台安全增强版：应用身份以 Token 为唯一可信来源，`X-App-Code` 请求头已废弃）

## 1. 概述

nway-system 是企业级管理平台，向外部系统（子系统、微服务、第三方应用）开放以下能力：

| 能力类别 | 内容 | 典型场景 |
| --- | --- | --- |
| 应用认证 | OAuth2 风格 Token 签发（三种授权模式） | 服务端到服务端调用、子系统免登 |
| SSO 单点登录 | 授权码模式免登 | 用户从本系统跳转子系统无需二次登录 |
| 用户认证 | 账号密码 / 生物识别登录、JWT 签发与续期 | 子系统复用本系统账号体系 |
| 组织与用户数据查询 | 用户、部门树、岗位、字典 | 通讯录、组织架构同步 |
| 文件中心 | 上传、下载、预览、短时票据 | 业务附件、图片/视频/PDF 在线预览 |
| 消息发送 | 站内消息（按用户/部门/角色定向） | 业务通知 |
| 统一权限策略 | 用户级功能权限 + 数据范围下发 | 子应用权限中心，微服务数据权限过滤 |
| 菜单自注册 | 子应用自助注册/更新自身菜单 | 子应用发布新功能无需平台手动配置 |
| Webhook 事件推送 | 用户/部门/角色/数据权限变更事件 | 数据同步、缓存失效 |

**基础信息**

- 服务地址：`http://<host>:8081`（端口可配置）
- 上下文路径：`/nway-system`（下文所有接口均基于该前缀）
- 统一响应格式：

```json
{
  "code": 200,        // 200 成功，非 200 失败
  "msg": null,        // 错误描述
  "data": {}          // 业务数据
}
```

> 身份认证协议细节（用户 JWT 的 Claims、续期机制、登录安全策略等）详见《外部系统接入身份认证文档.md》，本文档覆盖对外能力的完整清单与调用方式。

### 1.1 接入方式决策（先选型，再对接）

接入 nway-system 前必须先区分接入形态，两者的身份模型完全不同：

| 接入形态 | 典型特征 | 身份来源 | 主要调用通道 |
| --- | --- | --- | --- |
| **平台承载的微前端子应用** | 菜单 `renderType` 为 `microApp` / `wujie` / `iFrame`，由 nway-system 宿主打开 | 宿主注入的**用户 JWT** | 登录态通用接口 + 子应用自身业务接口；组织/权限等数据由子应用后端代理获取 |
| **独立外部系统 / 子系统** | 独立门户访问，无宿主登录态 | 开放平台**应用身份**（`appCode` + `appSecret`），或 SSO | `/open/*` 开放接口 |
| 平台内部微服务 | 同信任域、服务间调用 | `/internal/*` 服务令牌 | 不在本文档范围 |

#### A. 平台承载的微前端子应用

**核心结论：身份认证与平台通用能力不走开放平台。** 只有需要组织/用户/权限数据、菜单自注册、低代码同步、Webhook 时，才由**子应用服务端**使用开放平台应用身份。

1. **身份识别（必须对接）**：宿主通过微前端通道注入当前用户 JWT：

   | 宿主方式 | 登录态获取 |
   | --- | --- |
   | micro-app | `window.microApp.getData()` 读取 `token` |
   | wujie | `window.$wujie.props` 读取 `token` |
   | iFrame | 子应用发送 `nway:auth-request`，宿主回发 `nway:auth` |

   子应用将 Token 写入 `sessionStorage` 的 `ds-token`，请求携带 `Authorization: Bearer <token>`，并订阅 `nway:auth-change:<appName>`（实例级）与 `nway:auth-change`（续期/登出）同步登录态。**不需要调用 `/login` 或 SSO 授权码换取 Token，不要通过 URL 传 Token。**

2. **可直接调用的登录态通用接口**（用户 JWT 鉴权，无需 scope、无需开放 Token；`ticketDownload` 为票据直链、匿名访问）：

   | 能力 | 接口 |
   | --- | --- |
   | 当前用户菜单 / 常用 | `GET /myMenu`、`GET /myMenu/userFav` |
   | 字典 | `GET /dict/queryByCode?dictCode=` |
   | 个人消息 | `GET /message/polling`、`GET /message/list`、`POST /message/read`、`POST /message/resend` |
   | 文件中心 | `POST /file/upload`、`GET /file/download/{id}`、`GET /file/preview/{id}`、`POST /file/ticket`、`GET /file/ticketDownload` |
   | 当前登录用户 | `GET /login/getLoginUser`、`POST /login/validateToken` |

3. **不要用用户 JWT 调用平台管理接口**：`/user`、`/dept`、`/role`、`/menu`、`/app`、`/tenant` 等接口在服务端映射为平台内置应用 `nway-system` 的资源 + 动作，仅平台管理员权限可访问。业务子应用不应为了查组织数据而给业务用户授予平台管理资源。

4. **子应用前端不能调用 `/open/*`**：开放接口会校验 Token 类型（必须是开放平台 Token），用户 JWT 调用 `/open/*` 一律返回 401；获取开放 Token 又必须使用 `appSecret`，**严禁下发到浏览器**。因此子应用前端"走开放平台"在技术上不成立。

5. **子应用后端识别当前用户**（二选一）：
   - 与平台共享 `JWT_SECRET` 本地验签（参考 `nway-app-oa` 的 `nway.host-jwt.secret` 配置）；
   - 携带用户 JWT 调用 `GET /login/getLoginUser` 获取用户信息（适合不希望共享密钥的场景，建议本地短时缓存）。

6. **确实需要用户 / 部门 / 岗位 / 权限策略数据时**：由子应用**后端**以应用身份代理当前用户：
   - 使用 `appCode` + `appSecret` 调 `POST /open/token`，`grantType=user_delegate`，`userToken` 传当前用户 JWT，换取开放 Token；
   - 再调用 `/open/org/*`、`/open/user/*`、`GET /open/permission/bundle` 等接口；
   - `GET /open/permission/bundle` 只接受开放 Token，并按 Token 中的 `appCode` 返回该用户在本应用下的策略，目前无"用户 JWT 版"等价接口；
   - 数据范围为应用 `dataScopeType` ∩ 代理用户数据权限（见第 5 节）。

7. **应用级集成仍走开放平台**：菜单自注册（`POST /open/menu/register`）、低代码菜单同步（`/open/lowcode/*`）、Webhook 订阅属于发布 / 运维通道，由子应用**服务端**使用应用身份调用，与用户访问链路分离。

#### B. 独立外部系统 / 子系统

无宿主登录态的系统按第 2 节注册开放平台应用，通过 `/open/token` 获取开放 Token 后调用 `/open/*`；需要用户免登时使用 `authorization_code`（SSO）模式。

## 2. 接入准备：注册开放平台应用（仅需要应用身份时）

> 平台承载的微前端子应用**不需要**仅为用户登录或调用第 1.1 节 A.2 中的登录态通用接口而注册开放平台应用；仅当需要 `/open/*` 数据接口、菜单自注册、低代码同步或 Webhook 时注册，且调用方须为子应用服务端。

1. 联系平台管理员在管理端「系统管理 → 开放平台」创建应用，提供：
   - **应用编码**（`appCode`）：全局唯一，建议用系统名，如 `oa-system`
   - **应用名称**、负责人工号
2. 管理员按需配置：
   - **授权 Scope**（见第 4 节各接口所需 scope）
   - **数据范围**（`dataScopeType`）：`ALL` / `DEPT` / `DEPT_WITH_SUB` / `CUSTOM`（见第 5 节）
   - **限流**：每秒 / 每日请求上限
   - **IP 白名单**：留空不限
   - **有效期**：留空永不过期
3. 创建成功后系统**一次性返回明文 `appSecret`（64 位十六进制），请立即妥善保存**。平台仅存 BCrypt 哈希，遗失只能重置（重置后旧密钥立即失效）。

## 3. 认证

### 3.1 获取开放平台 Token

```
POST /nway-system/open/token
Content-Type: application/x-www-form-urlencoded
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `appCode` | 是 | 应用编码 |
| `appSecret` | 是 | 应用密钥（明文） |
| `grantType` | 是 | `client_credentials` / `user_delegate` / `authorization_code` |
| `userToken` | 条件必填 | `user_delegate` 模式：已登录用户的 JWT |
| `code` | 条件必填 | `authorization_code` 模式：SSO 授权码 |
| `targetTenantCode` | 否 | `user_delegate` 模式：数据作用域租户，须 ∈ 代理用户可管理租户，缺省为应用所属租户 |

> 代理用户可管理的租户列表可通过 `GET /open/tenant/manageable` 查询（仅 `user_delegate` / `authorization_code` 模式可用）。

响应：

```json
{
  "code": 200,
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiJ9...",
    "token_type": "Bearer",
    "expires_in": 7200,
    "scope": "user:read org:read",
    "employee_id": "EMP001"
  }
}
```

**三种授权模式**：

| 模式 | 用户上下文 | 典型场景 |
| --- | --- | --- |
| `client_credentials` | 无（应用身份） | 服务端到服务端的数据同步、批量查询 |
| `user_delegate` | 有（代理用户） | 外部系统已持有用户 JWT，代表该用户访问 |
| `authorization_code` | 有（SSO 用户） | 子系统 SSO 免登 |

**Token 特性**：

- 有效期 **2 小时**，无 refresh_token，到期重新调用 `/open/token` 获取
- 使用独立密钥签名（`JWT_OPEN_SECRET`，未配置时降级 `JWT_SECRET`），与用户 Token 互不通用
- Token 内嵌 `scope`、数据范围、代理用户等信息，服务端从 Token 解析，不回查配置
- **应用身份唯一来源是 Token**；`X-App-Code` 请求头已废弃（传递也会被忽略）
- 开放 Token 只能调用 `/open/*` 接口；用户 JWT 不能调用 `/open/*` 接口

### 3.2 调用开放 API

```
GET /nway-system/open/user/getByEmployeeId?employeeId=EMP001
Authorization: Bearer <access_token>
```

服务端依次校验：Token 验签 → Scope → IP 白名单 → 限流 → **数据范围过滤**（见第 5 节）→ 审计日志。

### 3.3 SSO 单点登录（authorization_code）

适用：用户在 nway-system 登录后跳转子系统免登。

> 平台承载的微前端子应用无需使用本模式：宿主已注入用户 JWT，见第 1.1 节 A。

1. 子系统前端在用户已登录状态下调用：

```
POST /nway-system/login/sso/authorize?appCode=<appCode>&redirectUri=<子系统回调地址>
Authorization: Bearer <用户JWT>
→ 200 { "data": { "code": "a1b2c3...", "redirectUri": "https://sub.example.com/callback" } }
```

2. 前端 302 重定向到 `redirectUri?code=<授权码>`。
3. 子系统后端用授权码换取开放 Token（见 3.1，`grantType=authorization_code`），响应中 `employee_id` 即 SSO 用户工号，据此建立本地会话。

安全要点：授权码 32 位随机串，**5 分钟有效、一次性消费**、绑定 appCode；子系统应自行校验回调地址（建议保存随机 state 参数防 CSRF）。

### 3.4 用户账号登录认证

子系统如需代替用户完成登录（复用本系统账号体系），调用：

```
POST /nway-system/login
{ "name": "EMP001", "key": "password", "loginType": "password", "clientType": "PC" }
```

返回用户 JWT（默认 24 小时有效，剩余不足 5 分钟可通过 `POST /login/refresh` 续期，时长均可通过环境变量调整）。JWT 校验、续期限制、登录安全策略详见《外部系统接入身份认证文档.md》。

## 4. 开放 API 清单

| 模块 | Scope | 接口 | 说明 |
| --- | --- | --- | --- |
| 用户 | `user:read` | `GET /open/user/getByEmployeeId?employeeId=` | 按工号查用户基本信息（数据范围外返回 404） |
| 用户 | `user:read` | `GET /open/user/queryByDept?deptId=` | 按部门查用户列表（部门须在数据范围内） |
| 用户 | `user:write` | `POST /open/user/validateToken?token=` | 验证用户 JWT 是否有效，返回 `{valid}`（POST 按规则推导为 `user:write`） |
| 用户 | `user:read` | `GET /open/user/search?keyword=&deptId=&includeSub=&current=&size=` | 关键字分页搜索用户（姓名/工号/手机号，可按部门含子树） |
| 组织 | `org:read` | `GET /open/org/deptTree` | 部门树（按数据范围过滤） |
| 组织 | `org:read` | `GET /open/org/positions` | 启用岗位列表 |
| 组织 | `org:read` | `GET /open/org/usersByPosition?positionId=` | 按岗位查用户（含姓名、部门名称） |
| 字典 | `dict:read` | `GET /open/dict/items?dictCode=` | 按编码查启用字典项 |
| 消息 | `msg:send` | `POST /open/msg/send` | 发送站内消息 |
| 权限策略 | `permission:read` | `GET /open/permission/bundle?employeeId=` | **推荐**：用户在当前应用下的策略包（版本号 + 资源动作 + 数据谓词），支持 `If-None-Match` / ETag 缓存 |
| 权限策略 | `permission:read` | `GET /open/permission/policies?employeeId=` | 用户在当前应用下的权限策略（**已弃用**，保留一个版本供存量 SDK 迁移） |
| 权限策略 | `permission:read` | `GET /open/permission/check?employeeId=&resourceCode=&action=` | 快捷校验某操作权限，返回 `{true/false}` |
| 资源目录 | 无（仅校验 Token） | `GET /open/meta/catalog` | 查询当前应用可配置的资源与动作（由菜单 `resource_code` + BTN `action` 构建） |
| 文件 | `file:read` | `GET /open/file/query` | 分页查询文件元数据 |
| 文件 | `file:read` | `GET /open/file/get/{id}` | 按 ID 查询文件元数据 |
| 文件 | `file:read` | `GET /open/file/download/{id}` | 下载文件，支持 HTTP Range |
| 文件 | `file:read` | `GET /open/file/preview/{id}` | 内联预览，支持 HTTP Range |
| 文件 | `file:write` | `POST /open/file/ticket` | 生成短时预览/下载票据（POST 按规则推导为 `file:write`） |
| 文件 | `file:write` | `POST /open/file/upload` | 上传文件（multipart） |
| 菜单 | `menu:write` | `POST /open/menu/register` | 子应用全量注册/更新自身菜单 |
| 菜单 | `menu:read` | `GET /open/menu/list` | 查询本应用已注册菜单 |
| 低代码菜单 | `menu:read` | `GET /open/lowcode/apps` | 查询当前租户下可发布的应用列表 |
| 低代码菜单 | `menu:read` | `GET /open/lowcode/menu/tree` | 查询应用下菜单树（选择父级菜单用） |
| 低代码菜单 | `menu:write` | `POST /open/lowcode/menu/sync` | 低代码页面/目录菜单同步（幂等 upsert） |
| 低代码菜单 | `menu:write` | `POST /open/lowcode/menu/remove` | 删除 LOWCODE 来源菜单 |
| 低代码菜单 | `menu:write` | `POST /open/lowcode/menu/disable` | 停用 LOWCODE 来源菜单（保留配置） |
| 租户 | `tenant:read` | `GET /open/tenant/current` | 查询应用所属租户信息 |
| 租户 | `tenant:read` | `GET /open/tenant/manageable` | 查询代理用户可管理的租户列表（仅代理用户模式） |

> Scope 推断规则：`GET /open/{module}/*` → `{module}:read`；其他方法 → `{module}:write`（例外：`msg:send`、`dp:check`、低代码菜单 `/open/lowcode/*` → `menu:read` / `menu:write`；`/open/meta/*` 不要求 scope）。管理端调整 scope 后，**新签发的 Token 生效**。

### 4.1 发送站内消息

```
POST /nway-system/open/msg/send
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{
  "title": "合同审批提醒",
  "content": "您有一份合同待审批",
  "senderId": "oa-system",
  "senderName": "OA 系统",
  "channels": ["inbox"],
  "targets": [
    { "targetType": 1, "targetId": "EMP001" },
    { "targetType": 2, "targetId": "D001" },
    { "targetType": 3, "targetId": "R001" }
  ]
}
```

`targetType`：`1`=用户（targetId=工号）、`2`=部门（targetId=部门id）、`3`=角色（targetId=角色id）。响应 `data` 为消息 id。

### 4.2 菜单自注册

子应用部署新功能后，全量替换自己在平台的菜单（`source=APP`，不影响平台管理员配置的 PLATFORM 菜单）。该接口由子应用**服务端**调用，开放 Token 不得下发浏览器：

```
POST /nway-system/open/menu/register
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
[
  {
    "name": "订单管理",
    "parentId": "",
    "menuType": "DIR",
    "icon": "order",
    "renderType": "microApp"
  },
  {
    "name": "订单列表",
    "parentId": "<上级菜单id>",
    "menuType": "PAGE",
    "url": "/order/list",
    "renderType": "wujie",
    "resourceCode": "order-list"
  }
]
```

| 字段 | 说明 |
| --- | --- |
| `name` | 菜单名称 |
| `parentId` | 上级菜单 id，顶级传空串 |
| `menuType` | `DIR`(目录) / `PAGE`(页面) / `BTN`(按钮) |
| `url` | 页面路由路径（相对于应用注册的 host） |
| `renderType` | 渲染方式：`microApp` / `wujie` / `iFrame`（`iFrame` 仅适用于**无需平台登录态**的系统：该通道没有 Token 注入能力） |
| `resourceCode` | PAGE 类型必填，与权限策略 `resource_code` 对应，用于控制菜单可见性 |

> 注册为**全量替换**：每次调用会删除本应用旧的 APP 菜单后重新写入，请一次性提交完整菜单树。`appCode`、租户、来源标记由服务端按 Token 自动填充。

### 4.3 权限策略下发

`GET /open/permission/policies?employeeId=EMP001` 返回该用户在**当前应用**（Token appCode）下的合并策略列表：

```json
{
  "code": 200,
  "data": [
    {
      "appCode": "order-system",
      "resourceCode": "order",
      "actions": ["view", "create"],
      "dataScope": "DEPT_WITH_SUB",
      "deptIds": ["1", "101"],
      "deptCodes": ["01", "0102"]
    }
  ]
}
```

- `actions` 为 `null` 表示全部操作；`resourceCode` 为 `*` 表示应用级通配策略
- `dataScope` 取值：`ALL` / `SELF` / `DEPT` / `DEPT_WITH_SUB` / `CUSTOM` / `EXPRESSION`（子应用场景建议管理员使用前五种，EXPRESSION 子应用侧按主部门回退）
- `deptCodes` 用于 `DEPT_WITH_SUB` 的编码前缀匹配（依赖部门层级编码规范）

### 4.4 低代码页面菜单同步

低代码平台将配置的页面/目录同步注册为系统菜单（来源标记 `source=LOWCODE`，不影响平台管理员配置的 `PLATFORM` 菜单与子应用自注册的 `APP` 菜单）。

**接入要求**：

- 仅支持 `user_delegate` 授权模式获取 Token（用户在低代码平台操作发布，Token 携带该用户上下文），**不支持 `client_credentials`**
- 用户/租户身份取自 Token 代理用户：只能查询和发布**代理用户所属租户**下的应用
- 所需 scope：`menu:read` + `menu:write`
- 页面路由路径相对目标应用注册的 `app.host` 拼接；渲染类型缺省 `wujie`（页面由目标应用以微前端方式承载）
- 渲染器选型建议：自有 Vue3 SPA 用 `wujie`（默认）；某个库在 wujie 下兼容异常时改 `microApp`；需真隔离或目标站点对注入不友好时用 `*-iframe`；目标站点禁止被 iframe 嵌入（`X-Frame-Options` / `CSP frame-ancestors`）时必须用注入式（`microApp` / `wujie`）

#### 4.4.1 查询可发布应用

```
GET /nway-system/open/lowcode/apps
Authorization: Bearer <access_token>
```

响应 `data`（仅返回当前租户下 `status=using` 的应用）：

```json
[{ "appCode": "order-system", "appName": "订单系统", "host": "http://order.example.com" }]
```

#### 4.4.2 查询应用菜单树（选择父级菜单）

```
GET /nway-system/open/lowcode/menu/tree?appCode=order-system
Authorization: Bearer <access_token>
```

响应 `data`：仅返回 `DIR`/`PAGE` 类型菜单（`BTN` 不返回），含 `menuId`、`parentId`、`name`、`type`、`url`、`externalId`、`visible`。应用本身即根节点（`parentMenuId` 传空串表示挂应用根）。

#### 4.4.3 菜单同步（核心）

```
POST /nway-system/open/lowcode/menu/sync
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{
  "appCode": "order-system",
  "grantRoleCodes": ["R_ORDER_ADMIN"],
  "items": [
    {
      "externalId": "lc-dir-1001",
      "type": "DIR",
      "name": "报表中心",
      "icon": "report",
      "sequence": 1
    },
    {
      "externalId": "lc-page-2001",
      "externalParentId": "lc-dir-1001",
      "type": "PAGE",
      "name": "销售订单",
      "url": "/lowcode/sales-order/list",
      "resourceCode": "lc.sales-order",
      "sequence": 1
    },
    {
      "externalId": "lc-page-2001-detail",
      "externalParentId": "lc-dir-1001",
      "type": "PAGE",
      "name": "销售订单详情",
      "url": "/lowcode/sales-order/detail/:id",
      "resourceCode": "lc.sales-order",
      "visible": false
    }
  ]
}
```

**字段说明**：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `appCode` | 是 | 目标应用编码，须为代理用户租户下 `using` 状态的应用 |
| `grantRoleCodes` | 否 | 发布后自动授权的角色编码列表（见下文"自动授权"） |
| `items[].externalId` | 是 | 低代码侧唯一标识（页面 id / 目录 id），**幂等键**：重复发布=更新，不做全量替换 |
| `items[].parentMenuId` | 二选一 | 本系统已有父菜单 id（通过 4.4.2 查询），须为同应用下 `DIR` |
| `items[].externalParentId` | 二选一 | 同批次某项的 `externalId`（须为 `DIR`），或**历史批次已发布**的 LOWCODE 节点标识（增量挂载）。与 `parentMenuId` 互斥 |
| `items[].type` | 是 | `DIR`(目录)/`PAGE`(页面)，对应低代码平台的目录与页面；不支持 `BTN` |
| `items[].name` | 是 | 菜单名称 |
| `items[].url` | PAGE 必填 | 页面路由路径（相对 `app.host`）；`DIR` 不可携带 |
| `items[].resourceCode` | PAGE 必填 | 资源标识，与权限策略关联，控制菜单可见性 |
| `items[].renderType` | 否 | `microApp`/`wujie`/`iFrame`，缺省 `wujie` |
| `items[].visible` | 否 | 缺省 `true`。表单**详情/编辑形态**传 `false`：可路由、可授权，但不进导航菜单 |
| `items[].isEnabled` | 否 | 缺省 `true` |
| `items[].sequence` | 否 | 组内排序 |

**父级引用"双轨制"语义**：

| 状态 | 两父级字段都空 | `parentMenuId` | `externalParentId` |
| --- | --- | --- | --- |
| 新建 | 挂应用根 | 挂该菜单下 | 挂引用节点下 |
| 更新 | **保持原父级不变** | 移动到该菜单下 | 移动到引用节点下 |

> ⚠️ "更新时都空=保持原父级"与"新建时都空=挂根"语义不同：增量发布时未显式指定父级的已有页面**不会被挪动**，这是防止误操作的保护性设计。
> 挂载关系成环（如把目录挂到自己的子孙下）会被整体拒绝。

**响应**（逐项回执，`parentId` 为解析后的最终父菜单 id，供核对挂载结果）：

```json
{
  "code": 200,
  "data": {
    "results": [
      { "externalId": "lc-dir-1001", "menuId": "1024", "parentId": "", "status": "CREATED" },
      { "externalId": "lc-page-2001", "menuId": "1025", "parentId": "1024", "status": "CREATED" },
      { "externalId": "lc-page-2001-detail", "menuId": "1026", "parentId": "1024", "status": "UPDATED" }
    ],
    "warnings": []
  }
}
```

同步为**原子操作**：整批校验（externalId 唯一、类型合法、父级存在且为 DIR、无环、应用归属租户）全部通过后落库，任一失败整体拒绝并返回错误信息。

**自动授权**：

- 本系统菜单可见性由权限策略推导（用户在页面 `resourceCode` 上有任意 action 权限 → 可见），**新发布页面默认无人可见**
- `grantRoleCodes` 指定的角色将为本次所有可见页面（`visible=true` 且 `resourceCode` 非空）幂等创建 `(resourceCode, actions=["view"])` 策略
- 自动创建的策略数据范围为最保守的 `SELF`，页面内数据权限应由管理员按需调整
- 角色不存在 / 不属于当前租户 / 目标应用不在角色租户可授权范围（本租户私有应用与 public 共享应用）内时**不阻断发布**，逐条记入响应 `warnings`；角色 `app_code` 只是主应用，同租户跨应用（如共享应用角色授权租户低代码应用）会被放行
- 详情/编辑等隐藏页面（`visible=false`）不单独授权，复用列表页 `resourceCode` 的策略即可（同名 resourceCode 下任意 action 权限即可路由可达）

#### 4.4.4 删除 / 停用菜单

低代码平台侧删除或下线页面后应主动同步：

```
POST /nway-system/open/lowcode/menu/remove     # 删除（存在子菜单时整批拒绝，防止误删子树）
POST /nway-system/open/lowcode/menu/disable    # 停用（保留配置，推荐下线场景使用）
Authorization: Bearer <access_token>
Content-Type: application/json

{ "appCode": "order-system", "externalIds": ["lc-page-2001", "lc-page-2001-detail"] }
```

- 仅作用于 `LOWCODE` 来源菜单，平台管理员配置的菜单不受影响
- `externalIds` 未命中的忽略（幂等）；删除后重新发布同 `externalId` 视为新建

### 4.5 用户搜索（选人组件场景）

供外部系统的「选人」组件做候选人检索：按关键字（姓名 / 工号 / 手机号模糊）+ 部门过滤，分页返回。

```
GET /nway-system/open/user/search?keyword=张&deptId=<部门id>&includeSub=true&current=1&size=15
Authorization: Bearer <access_token>
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `keyword` | 否 | 姓名 / 工号 / 手机号 模糊匹配 |
| `deptId` | 否 | 部门 id（须在数据范围内，否则返回空列表） |
| `includeSub` | 否 | `deptId` 非空时是否包含下级部门（按部门层级编码前缀展开），缺省 `false` |
| `current` / `size` | 否 | 页码（缺省 1）/ 每页条数（缺省 15，上限 100） |

响应 `data`：`{ "data": [ { "employeeId", "realName", "phoneNumber", "email", "avatar", "status", "deptId", "deptName" } ], "total": 42 }`

- 只返回启用（`using`）人员；租户由 Token 强绑定，不接受租户参数。
- 数据范围同其它 `/open/*` 查询接口（应用范围 ∩ 代理用户数据权限）；范围外部门直接返回空列表（fail-closed）。
- 手机号返回明文（选人场景需要展示与检索）；如需脱敏请另行约定。
- ⚠️ 应用 `dataScopeType` 建议配置为 `ALL`：配置为 `CUSTOM/DEPT/DEPT_WITH_SUB` 时只能检索到范围内部门与人员。

### 4.6 文件中心

外部系统通过 `/open/file/**` 接入文件上传、查询、下载、预览与短时票据，所需 scope 为 `file:read` / `file:write`。完整接口、`@nway/file` SDK 与组件用法见《[文件管理对接文档](文件管理对接文档.md)》。

## 5. 数据范围（Data Scope）

`/open/*` 数据查询接口的返回结果受**两层数据范围取交集（更严者生效）**约束：

1. **应用数据范围**（管理端为应用配置的 `dataScopeType`）：
   - `ALL`：不限制
   - `CUSTOM` / `DEPT` / `DEPT_WITH_SUB`：按配置的部门集合过滤（含子树展开）
   - ⚠️ 应用身份无"本部门"概念：配置为 DEPT/DEPT_WITH_SUB/CUSTOM 时**必须同时配置部门集合**，否则 fail-closed（拒绝返回数据）
2. **代理用户数据权限**（`user_delegate` / `authorization_code` 模式）：取代理用户在平台的统一权限策略（`nway-system:user` 资源）：
   - `ALL` 不限制；`SELF` 仅本人；`DEPT` 主部门；`DEPT_WITH_SUB` 主部门及子树；`CUSTOM` 自定义部门集合；`EXPRESSION` 按主部门回退；**无策略按 SELF（拒绝）**

| 接口 | 过滤方式 |
| --- | --- |
| `getByEmployeeId` | 范围外用户返回 404（不泄露存在性） |
| `queryByDept` | 请求部门不在范围内返回空列表 |
| `search` | 请求部门不在范围内返回空列表；无部门条件时仅返回范围内部门的人员 |
| `deptTree` | 仅返回范围内部门及其祖先链 |
| `usersByPosition` | 仅返回主部门在范围内的人员 |
| `dict/items`、`positions`、`msg/send`、`menu/*`、`permission/*`、`tenant/current` | 不做数据范围过滤（全局数据/操作类接口） |

## 6. 配套 SDK：数据权限下沉到外部服务（Java 微服务推荐）

`nway-system-authz-sdk`（坐标 `com.nway.system:nway-system-authz-sdk:1.0.0`，JDK 21+）封装了权限策略的拉取与 SQL 过滤执行，适合需要在本服务内做**行级数据权限过滤**的微服务。

**运行时行为（内置）**：

- 策略拉取：自动获取/刷新应用 Token（过期前 5 分钟主动刷新），401 强制刷新后重试一次
- 本地缓存：Caffeine 1 分钟 TTL（单机最多 5000 个用户）
- 熔断：平台不可用时熔断 30 秒后自动恢复探测
- **fail-closed**：平台不可用 / 获取策略失败时按"拒绝所有数据"处理，不会放权

### 6.1 接入步骤

**第一步：引入依赖**

```xml
<dependency>
    <groupId>com.nway.system</groupId>
    <artifactId>nway-system-authz-sdk</artifactId>
    <version>1.0.0</version>
</dependency>
```

**第二步：添加配置**（Spring Boot 自动装配，配置 `nway.permission.platform-url` 即生效）

```yaml
nway:
  permission:
    platform-url: http://<host>:8081/nway-system
    app-code: order-system
    app-secret: <应用密钥>    # 推荐；旧方式仅配 app-token 已过时（2 小时过期需自行更换）
```

**第三步：实现 `CurrentUserResolver` SPI**（AOP 注解方式的前置条件）

SDK 通过该接口获取当前请求用户，返回 Map 至少包含 `user.employeeId`（通常从本服务会话/网关透传头中解析）：

```java
@Component
public class MyUserResolver implements CurrentUserResolver {
    @Override
    public Map<String, Object> resolve() {
        String employeeId = ...; // 从本服务登录态解析
        if (employeeId == null) {
            return null;         // 无用户上下文返回 null
        }
        return Map.of("user.employeeId", employeeId);
    }
}
```

> ⚠️ AOP 拦截器仅在 classpath 存在 AspectJ **且容器中存在 `CurrentUserResolver` Bean** 时才自动注册；未注册时注解方式不生效，请改用 6.3 编程式调用。
> ⚠️ `resolve()` 返回 null 或缺少 `user.employeeId` 时，SDK **不注入过滤条件直接放行**——用户上下文缺失的拦截应由认证层（网关/过滤器）保证。

**第四步：标注注解或编程式调用**（见下文）

### 6.2 注解方式（推荐）

在 DAO/Service 方法上标注 `@DataPermission`，AOP 拦截器自动拉取策略、构建数据范围 WHERE 条件并存入 `DataPermissionContext`（ThreadLocal），方法执行后自动清理：

```java
@DataPermission(resource = "contract")
public Page<Contract> queryPage(ContractQuery query) { ... }
```

| 注解参数 | 默认值 | 说明 |
| --- | --- | --- |
| `resource` | 必填 | 资源标识，对应平台权限策略的 `resourceCode` |
| `deptIdField` | `dept_id` | 业务表部门 ID 字段名（DEPT/CUSTOM 范围使用） |
| `deptCodeField` | `dept_code` | 业务表部门编码字段名（DEPT_WITH_SUB 前缀匹配使用） |
| `creatorField` | `creator_id` | 业务表创建人字段名（SELF 范围使用） |

DAO 层构建 SQL 时从 `DataPermissionContext.getWhereSql()` 读取片段并 `AND` 追加。

### 6.3 编程式调用

需要自行控制 SQL 拼接位置时，直接使用 `PermissionFilter`：

```java
ResourcePolicy policy = client.getPolicy(employeeId, "contract");
SqlFragment fragment = PermissionFilter.buildDataScopeWhere(
        policy, PermissionFilter.FieldMapping.DEFAULT, Map.of("user.employeeId", employeeId));
if (fragment != null) {                       // null = ALL 不限制
    sql += " AND " + fragment.sql();
    params.addAll(fragment.params());
}
```

**数据范围 → WHERE 条件映射**：

| dataScope | 生成条件 | 说明 |
| --- | --- | --- |
| 策略为 null | `1 = 0` | 无策略 = 拒绝所有 |
| `ALL` | 不追加条件 | 不限制 |
| `SELF` | `creator_id = ?` | 仅本人 |
| `DEPT` / `CUSTOM` | `dept_id IN (?,?,...)` | 按策略下发的部门 id 集合；集合为空时 `1 = 0` |
| `DEPT_WITH_SUB` | `dept_code LIKE ? ESCAPE '\'` OR ... | 按部门编码前缀匹配子树；需业务表维护 `dept_code` 层级编码 |
| `EXPRESSION` / 未知值 | `1 = 0` | SDK fail-closed 拒绝（比平台 `/open/*` 的主部门回退更严格）；建议管理员仅使用前五种范围 |

`ResourcePolicy` 还提供 `hasAction(action)` / `actions`（null = 全部操作）用于功能权限校验，等价于 `GET /open/permission/check`。

### 6.4 非 Java 系统对接

直接轮询 `GET /open/permission/policies?employeeId=`（需 `permission:read` scope）自行实现过滤逻辑，要求：

- 本地缓存 ≤ 1 分钟（或订阅 `data_permission.changed` Webhook 主动失效，见第 7 节）
- 获取失败时按"拒绝所有数据"处理（fail-closed），与 SDK 行为对齐

## 7. Webhook 事件回调

外部系统可订阅事件，平台在事件发生时以 HTTP POST 异步推送。订阅方式：管理端「开放平台 → Webhook」配置事件类型、回调 URL、HMAC 签名密钥（自行设置）、重试次数（默认 3）。

**支持的事件**：

| 事件 | 说明 |
| --- | --- |
| `user.created` / `user.updated` / `user.disabled` | 用户创建 / 变更 / 禁用 |
| `dept.changed` | 部门变更 |
| `role.changed` | 角色变更 |
| `data_permission.changed` | 数据权限变更 |

**回调格式**：

```
POST <callbackUrl>
Content-Type: application/json
X-Webhook-Signature: <HMAC-SHA256 十六进制小写签名>
X-Webhook-Event: user.created

{ "eventType": "user.created", "timestamp": 1724030000000, "data": { } }
```

**签名验证（接收方必须执行）**：`HMAC-SHA256(secret, 原始请求体字符串)`，密钥为订阅时配置的 secret，十六进制小写；建议同时校验 `X-Webhook-Event` 与请求体 `eventType` 一致。

**重试策略**：非 2xx 或网络异常时重试，最多 `retryCount` 次，指数退避（1s、2s、4s…），接收方应做幂等处理。

## 8. 错误码

| code | 含义 | 说明 |
| --- | --- | --- |
| 200 | 成功 | — |
| 400 | 参数错误 | 参数缺失或格式错误 |
| 401 | 认证失败 | 应用不存在 / 已禁用 / 已过期 / 密钥错误 / Token 无效或过期 |
| 403 | 无权限 | 缺少 scope / IP 不在白名单 / 无接口权限 |
| 404 | 资源不存在 | 如数据范围外用户（按不存在处理） |
| 429 | 请求过于频繁 | 触发每秒 / 每日限流 |
| 500 | 服务端错误 | 系统内部错误 |
| 1006 | 账号已锁定 | 登录时账号被禁用 |
| 1008 | 登录失败次数过多 | 触发临时锁定或 IP 限流 |

## 9. 接入 Checklist 与安全最佳实践

### Checklist

- [ ] 先按第 1.1 节判断接入形态：平台微前端子应用走宿主注入的用户 JWT；独立外部系统才注册开放平台应用
- [ ] 管理端创建应用，保存 `appCode` / `appSecret`，配置 scope、数据范围、限流、IP 白名单
- [ ] 服务端通过 `POST /open/token` 获取 Token，仅存服务端，勿下发浏览器
- [ ] 调用 `/open/*` 时携带 `Authorization: Bearer <token>`，**不再传 X-App-Code**
- [ ] Token 过期（2 小时）自动重新获取；对 401 / 403 / 429 做重试与告警
- [ ] 如做 SSO：接入 `/login/sso/authorize` + `authorization_code`，校验回调地址防 CSRF
- [ ] 如订阅 Webhook：实现 HMAC-SHA256 签名验证、幂等处理、异步落库
- [ ] Java 微服务建议直接引入 `nway-system-authz-sdk`

### 安全最佳实践

1. **密钥安全**：`appSecret` 仅服务端持有；传输走 HTTPS。
2. **最小权限**：按需申请 scope，避免 `*` 通配；数据范围优先窄配置。
3. **数据范围必配部门集合**：应用身份模式下配置 DEPT/DEPT_WITH_SUB/CUSTOM 必须同时配置部门集合，否则接口返回空。
4. **令牌时效**：开放 Token 2 小时过期无刷新，服务端实现自动续取；SDK 已内置。
5. **缓存一致性**：自行轮询策略时本地缓存不超过 1 分钟，失败 fail-closed。
