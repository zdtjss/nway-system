# 文件上传与预览前端能力

> 适用对象：平台内页面、接入 nway-system 的外部系统前端
> 代码位置：`nway-system-web/packages/file`
> 包入口：`@nway/file`（零运行时依赖客户端）、`@nway/file/vue`（Vue 3 组件）
> 后端接口、存储与票据协议见 [文件管理对接文档](../../nway-system-service/docs/文件管理对接文档.md)

## 1. 能力概览

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 上传 | `FileClient.upload` / `FileUpload` | XHR 上传，支持进度、取消、失败重试 |
| 查询 | `FileClient.queryPage` | 文件名、业务类型、上传人、时间范围分页查询 |
| 元数据 | `FileClient.getById` | 按文件 ID 获取 `FileMeta` |
| 删除 | `FileClient.remove` | 仅 `internal` 模式；逻辑删除元数据 |
| 票据 | `FileClient.createTicket` | 申请短时预览/下载票据，供 `<img>` / `<video>` 使用 |
| 下载 | `FileClient.download` | Header 鉴权下载并触发浏览器保存 |
| 上传列表 | `FileUpload` | 选择/拖拽、校验、进度、取消、重试、移除、预览、下载 |
| 预览弹窗 | `FilePreview` | 图片缩放/旋转/拖动、视频播放、PDF 阅读、其他下载 |

包结构：

```text
nway-system-web/packages/file/
├── package.json                 # name: @nway/file，exports: "." / "./vue"
└── src/
    ├── index.ts                 # 零依赖客户端（fetch + XHR）
    ├── types.ts                 # FileMeta / FileClient / FileClientError 等类型
    └── vue/
        ├── index.ts             # @nway/file/vue 入口
        ├── FileUpload.vue       # 上传 + 文件列表
        ├── FilePreview.vue      # 图片/视频/PDF 预览弹窗
        └── fileType.ts          # 预览类型判定与格式化工具
```

依赖说明：

- `@nway/file` 核心客户端零运行时依赖，任何框架可用。
- `@nway/file/vue` 依赖 `vue`（可选 peer，版本 `^3.3.0`）。
- PDF.js 兜底预览使用 `pdfjs-dist`，已列入包依赖。

## 2. 引用方式

### 2.1 平台内（nway-system-web）

平台已配置好别名，直接引用，无需 `npm install`：

```ts
import { createFileClient } from '@nway/file'
import { FileUpload, FilePreview } from '@nway/file/vue'
```

别名位置：

- `nway-system-web/vite.config.ts`：`@nway/file` / `@nway/file/vue`
- `nway-system-web/tsconfig.app.json`：`paths`

### 2.2 外部系统

包以源码形式提供，`package.json` 的 `main` / `module` / `types` 均指向 `src/index.ts`，调用方需要具备 TS + Vue SFC 编译能力（Vite、webpack + ts-loader 等）。

可选方式：

```bash
# 1. 本地路径依赖
npm install <path-to>/nway-system-web/packages/file

# 2. 复制 packages/file 到外部系统源码中，并自行配置 @nway/file 别名

# 3. 发布到私有 npm 仓库后按普通依赖安装
```

外部系统如果不用 Vue，只引用 `@nway/file` 核心客户端即可，不会引入 Vue。

### 2.3 鉴权模式

| 模式 | `mode` | Token 来源 | 接口前缀 |
| --- | --- | --- | --- |
| 平台登录用户 | `internal`（默认） | 用户 JWT | `/file/**` |
| 外部系统应用 | `open` | 开放平台 Token | `/open/file/**` |

## 3. 创建客户端

```ts
import { createFileClient } from '@nway/file'

// 平台内：用户 JWT
const internalClient = createFileClient({
  baseUrl: 'https://host/nway-system',
  getToken: () => getToken() || ''
})

// 外部系统：开放平台 Token
const openClient = createFileClient({
  baseUrl: 'https://host/nway-system',
  mode: 'open',
  getToken: () => getOpenPlatformToken()
})
```

`FileClientOptions`：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `baseUrl` | 是 | 服务地址，如 `https://host/nway-system`；开发环境可为 `/api/nway-system` |
| `getToken` | 是 | 返回用户 JWT 或开放平台 Token，支持 `Promise` |
| `mode` | 否 | `internal`（默认）/ `open` |
| `fetchImpl` | 否 | 自定义 fetch，便于测试或非浏览器环境 |

平台内复用同一个实例即可，参考 `nway-system-web/src/api/fileClient.ts`：

```ts
import { createFileClient } from '@nway/file'
import { getToken } from '@/utils/auth'

export const fileClient = createFileClient({
  baseUrl: import.meta.env.VITE_API_URL,
  getToken: () => getToken() || ''
})
```

## 4. FileClient API

### 4.1 方法一览

```ts
upload(file: File, options?: FileUploadOptions): Promise<FileMeta>

queryPage(params: FileQueryParams): Promise<{ data: FileMeta[]; total: number }>

getById(id: string): Promise<FileMeta>

remove(id: string): Promise<void>   // 仅 internal；open 模式抛出 403

createTicket(id: string, purpose?: 'preview' | 'download'): Promise<FileTicket>

download(id: string, fileName?: string): Promise<void>

resolveUrl(url: string): string
```

### 4.2 上传

```ts
const meta = await fileClient.upload(file, {
  bizType: 'factoryVisitApply',
  bizId: 'FV20261105001',
  remark: '现场照片',
  onProgress: (percent) => console.log(percent),
  signal: controller.signal
})
```

行为：

- 使用 `XMLHttpRequest`，因此支持上传进度与 `AbortController` 取消。
- `bizType` / `bizId` / `remark` 以 **query 参数**提交，文件放在 `FormData` 的 `file` 字段。
- 取消后的错误码为 `499`，`FileUpload` 会静默移除该上传项。
- 返回值为服务端 `FileVo` 对应的 `FileMeta`。

### 4.3 查询与元数据

```ts
const page = await fileClient.queryPage({
  fileName: '合同',
  bizType: 'contract',
  creatorId: 'EMP001',
  startTime: '2026-11-01 00:00:00',
  endTime: '2026-11-30 23:59:59',
  current: 1,
  size: 15
})

const meta = await fileClient.getById(page.data[0].id)
```

`queryPage` 内部请求：

- `internal`：`GET /file/queryPage`
- `open`：`GET /open/file/query`

### 4.4 票据

```ts
const ticket = await fileClient.createTicket(meta.id, 'preview')
img.src = fileClient.resolveUrl(ticket.url)
```

行为：

- `purpose`：`preview`（默认，`inline`）/ `download`（`attachment`）。
- 返回 `{ ticket, url, expiresIn }`，默认有效期 600 秒。
- `url` 已补全为可直接用于 `<img>` / `<video>` 的绝对地址；在 micro-app / wujie 沙箱下，媒体请求不会被 fetch 重写，必须使用绝对地址。
- 票据下载始终走内部匿名路径 `/file/ticketDownload`，即使客户端是 `open` 模式。
- 票据只绑定单个文件，有效期内可重复使用，视频 Range 会多次请求。

### 4.5 下载

```ts
await fileClient.download(meta.id, meta.fileName)
```

行为：

- 使用 `fetch` 携带 `Authorization`，拿到 `Blob` 后通过临时 `<a download>` 保存。
- 未传 `fileName` 时会先调用 `getById` 获取文件名，失败则用文件 ID 兜底。

### 4.6 删除

```ts
await fileClient.remove(meta.id)
```

- 仅 `internal` 模式可用，请求 `POST /file/delete`。
- `open` 模式直接抛出 `FileClientError(403, '开放平台接口不支持删除文件')`。
- 服务端为逻辑删除，物理文件保留。

### 4.7 错误类型

```ts
import { FileClientError } from '@nway/file'

try {
  await fileClient.upload(file)
} catch (e) {
  if (e instanceof FileClientError) {
    console.error(e.code, e.status, e.message)
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `code` | 业务码或 HTTP 状态；取消上传为 `499` |
| `status` | HTTP 状态；网络异常为 `0` |
| `message` | 服务端 `msg` 或兜底文案 |

### 4.8 类型

```ts
interface FileMeta {
  id: string
  fileName: string
  fileSize: number
  contentType: string
  fileExt: string
  bizType?: string
  bizId?: string
  remark?: string
  creatorId?: string
  creatorName?: string
  createTime?: string
  downloadUrl?: string
  previewUrl?: string
}

interface FileQueryParams {
  fileName?: string
  bizType?: string
  creatorId?: string
  startTime?: string
  endTime?: string
  current?: number
  size?: number
  [key: string]: unknown
}
```

## 5. FileUpload 组件

### 5.1 示例

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { FileUpload } from '@nway/file/vue'
import type { FileMeta } from '@nway/file'
import { fileClient } from '@/api/fileClient'

const attachments = ref<FileMeta[]>([])
const accept = '.jpg,.jpeg,.png,.gif,.webp,.bmp,.mp4,.webm,.ogg,.pdf,.doc,.docx,.xls,.xlsx,.ppt,.pptx,.txt,.csv,.zip,.rar,.7z'

function onUploaded(meta: FileMeta) {
  console.log('已上传', meta.id)
}

function onError(message: string) {
  console.error(message)
}
</script>

<template>
  <FileUpload
    v-model="attachments"
    :client="fileClient"
    biz-type="contract"
    :biz-id="contractId"
    multiple
    :limit="5"
    :max-size-mb="200"
    :accept="accept"
    @uploaded="onUploaded"
    @error="onError"
  />
</template>
```

### 5.2 Props

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `modelValue` | `[]` | 已上传文件列表（`v-model`），只存 `FileMeta`，不存 `Blob` |
| `client` | 必填 | `createFileClient` 创建的客户端 |
| `bizType` | 空 | 业务类型，随上传写入元数据 |
| `bizId` | 空 | 业务单据 ID，随上传写入元数据 |
| `remark` | 空 | 备注 |
| `multiple` | `true` | 是否允许一次选择多个文件 |
| `limit` | `5` | 文件数量上限；达到后隐藏上传入口 |
| `maxSizeMb` | `200` | 单文件大小上限（前端校验） |
| `accept` | 空 | 文件类型限制，支持 `.pdf`、`image/*`、`video/mp4`、精确 MIME |
| `disabled` | `false` | 只读模式，隐藏上传入口与移除按钮 |

### 5.3 Events

| 事件 | 参数 | 触发时机 |
| --- | --- | --- |
| `update:modelValue` | `FileMeta[]` | 上传成功或移除文件 |
| `uploaded` | `FileMeta` | 单个文件上传成功 |
| `removed` | `FileMeta` | 从表单列表移除文件 |
| `error` | `string` | 校验失败、上传失败、下载失败 |

### 5.4 Slots

`trigger`：自定义上传入口，替换默认的「上传附件」区域。

```vue
<FileUpload v-model="files" :client="fileClient">
  <template #trigger>
    <el-button>选择附件</el-button>
  </template>
</FileUpload>
```

### 5.5 行为说明

- **选择后立即上传**：组件在文件选择/拖拽后马上调用 `client.upload`，不存在“提交表单时统一上传”的批次概念。业务表单保存时只保存 `FileMeta` 中的 `id`。
- **校验顺序**：空文件 → 大小 → `accept` 类型 → 同名文件；任一失败通过 `error` 事件返回，不上传该项。
- **数量上限**：`modelValue.length + 上传中数量` 不得超过 `limit`，超出部分会提示并截断。
- **进度与取消**：上传中使用 `AbortController`，点击「取消」立即中断请求。
- **失败重试**：失败项保留在列表中，可点击「重试」重新上传。
- **移除不删除服务端文件**：`removed` 只从表单列表移除，不调用 `remove`，避免误删被其他业务引用的文件；服务端文件由文件管理页统一删除。
- **重名判断**：仅按文件名判断，同名的不同文件也会被拦截。
- **内置预览**：组件内部已集成 `FilePreview`，图片/视频/PDF 可直接预览，其他类型只提供下载。
- **样式变量**：主题色可通过 `--nway-file-accent` 覆盖，默认 `#409eff`。

## 6. FilePreview 组件

### 6.1 示例

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { FilePreview } from '@nway/file/vue'
import type { FileMeta } from '@nway/file'
import { fileClient } from '@/api/fileClient'

const visible = ref(false)
const current = ref<FileMeta | null>(null)
const previewable = ref<FileMeta[]>([])
</script>

<template>
  <FilePreview
    v-model="visible"
    :file="current"
    :files="previewable"
    :client="fileClient"
    @change="(file) => (current = file)"
  />
</template>
```

### 6.2 Props

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `modelValue` | 必填 | 是否显示预览弹窗（`v-model`） |
| `file` | `null` | 当前预览文件 |
| `client` | 必填 | 文件客户端 |
| `files` | `[]` | 可前后切换的文件列表；建议只传可预览类型 |

### 6.3 Events

| 事件 | 参数 | 触发时机 |
| --- | --- | --- |
| `update:modelValue` | `boolean` | 关闭弹窗 |
| `change` | `FileMeta` | 上一张/下一张切换 |

### 6.4 行为说明

- 弹窗通过 `Teleport` 挂到 `body`，`z-index: 3000`。
- **按需申请票据**：打开弹窗或切换文件时才调用 `createTicket`，不会在列表页批量申请。
- **图片**：支持放大/缩小（0.25 步进，范围 0.25~4）、旋转 90°、拖动、滚轮缩放、重置；支持上一张/下一张。
- **视频**：原生 `<video controls playsinline preload="auto">`，依赖后端 HTTP Range 才能拖动进度；浏览器自动播放策略可能拒绝 `play()`，此时保留首帧和控件由用户点击播放。
- **PDF**：同源且浏览器支持内置阅读器时用 `<iframe>`；跨源或浏览器不支持时用 PDF.js 连续滚动渲染，支持书签目录、上下页与懒渲染。PDF.js 的 CMap、标准字体、WASM 均随包加载，不依赖外网 CDN。
- **其他类型**：提示“该文件类型不支持在线预览”，提供下载按钮。
- **票据过期**：媒体加载失败时自动重新申请一次票据；仍失败则提示用户。
- **键盘**：`Esc` 优先退出全屏，再关闭弹窗；`←` / `→` 切换上一张/下一张。
- **全屏**：在浏览器视口内铺满弹窗，不调用原生全屏 API。

## 7. 工具函数

```ts
import {
  resolvePreviewKind,
  fileTypeLabel,
  formatFileSize,
  extOf,
  canPreviewPdfNatively,
  IMAGE_EXT,
  VIDEO_EXT,
  PDF_EXT
} from '@nway/file/vue'
```

| 函数/常量 | 说明 |
| --- | --- |
| `resolvePreviewKind(file)` | 返回 `image` / `video` / `pdf` / `other` |
| `fileTypeLabel(file)` | 返回 `IMG` / `VID` / `PDF` / 扩展名 / `FILE` |
| `formatFileSize(size)` | 字节数格式化为 `B/KB/MB/GB/TB` |
| `extOf(fileName)` | 从文件名推断小写扩展名 |
| `canPreviewPdfNatively()` | 判断浏览器是否内置 PDF 阅读器 |
| `IMAGE_EXT` / `VIDEO_EXT` / `PDF_EXT` | 预览类型扩展名集合 |

类型判定以服务端 `fileExt` 为准，`contentType` 作为兜底；SVG 默认不进入图片预览，避免脚本型 XSS。

```ts
import { createFileClient } from '@nway/file'

const fileClient = createFileClient({
  baseUrl: 'https://host/nway-system',

```

```vue
<script setup lang="ts">
import { ref } from 'vue'
```

## 10. 微前端与部署注意事项

1. **baseUrl 由调用方传入**：组件不读取宿主环境变量；平台内用 `VITE_API_URL`，外部系统用完整服务地址。
2. **票据地址必须是绝对地址**：micro-app / wujie 只重写 fetch/XHR，`<img>` / `<video>` 的 `src` 按宿主源解析；`createTicket` 已基于实际请求地址补全绝对路径。
3. **不要在 URL 传 Token**：JWT 走 `Authorization` Header；浏览器直链只使用短时票据。
4. **上传大小双重限制**：前端 `maxSizeMb` 只做提示，服务端 `nway.file.max-size` 与 `spring.servlet.multipart.max-file-size` 才是最终约束。
5. **本地存储多实例**：`FILE_STORAGE_ROOT` 需挂共享卷，否则会出现“实例 A 上传、实例 B 下载 404”。
6. **PDF 跨源**：跨源时后端 `X-Frame-Options` 会阻止 iframe 内嵌，组件会自动回退到 PDF.js。

## 11. 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 上传 401 | `getToken` 返回空或 Token 已过期；检查 `mode` 与 Token 类型是否匹配 |
| 上传 403 | 开放平台 Token 缺少 `file:write` scope |
| 上传 413 | Nginx / 网关 `client_max_body_size` 过小 |
| 上传提示“文件大小超过限制” | `maxSizeMb` 或服务端 `nway.file.max-size` 过小 |
| 上传提示“不在允许的文件类型范围” | 前端 `accept` 或服务端 `allowed-extensions` 未包含该扩展名 |
| 图片/视频 403 | 票据过期、票据与文件不匹配，或未使用 `ticketDownload` 地址 |
| 视频无法拖动 | 代理未透传 `Range`，或后端未返回 `206` / `Accept-Ranges` |
| PDF 预览空白 | 跨源且 iframe 被 `X-Frame-Options` 拦截；确认 PDF.js 资源已随包构建 |
| 外部系统跨域失败 | 未配置 `nway.file.cors-allowed-origins`，或未放行 `Authorization` |
| 下载中文名乱码 | 代理丢弃或改写了 `Content-Disposition` |
